# Проекты

Проект — контейнер для задач, объединённых общей целью. У проекта есть
участники, сроки, статус и настройки.

## <a id="создание-проекта">Создание проекта</a>

1. В разделе **Проекты** нажмите **Создать проект**.
2. Укажите **Название** и **Описание**.
3. Выберите **Тип проекта**: Канбан, Scrum, Список.
4. Добавьте **Участников** из списка пользователей.
5. Укажите **Дату начала** и **Срок окончания**.
6. Нажмите **Сохранить**.

### Типы проектов

| Тип | Для чего |
| --- | --- |
| Канбан | Непрерывный поток задач без фиксированных итераций |
| Scrum | Работа спринтами с планированием и ретроспективой |
| Список | Простой список задач без доски и спринтов |

## <a id="роли-участников">Роли участников</a>

| Роль | Права |
| --- | --- |
| Владелец | Полный доступ, управление проектом, удаление |
| Менеджер | Управление задачами, спринтами, участниками |
| Сотрудник | Создание и редактирование своих задач |
| Наблюдатель | Только просмотр, без права комментировать |

Роли назначаются в разделе **Проект → Участники → Изменить роль**.

!!! note "Несколько владельцев"
    У проекта может быть несколько владельцев. Это удобно при передаче
    проекта или при работе двух руководителей.

## <a id="спринты">Спринты</a>

Спринт — фиксированный промежуток времени (обычно 1–2 недели), в течение
которого команда выполняет запланированный объём задач.

### Создание спринта

1. Откройте проект → вкладка **Спринты**.
2. Нажмите **Создать спринт**.
3. Укажите **Название** (например, `Спринт 12`) и **Период**.
4. Добавьте задачи из бэклога проекта.
5. Нажмите **Запустить спринт**.

### Завершение спринта

После окончания периода:

1. Откройте спринт.
2. Нажмите **Завершить**.
3. Незавершённые задачи система предложит перенести в следующий спринт
   или вернуть в бэклог.

!!! tip "Диаграмма сгорания"
    На странице спринта доступна диаграмма сгорания (burndown chart).
    Она показывает, успевает ли команда закрыть задачи к концу итерации.

## <a id="вехи">Вехи</a>

Веха — ключевое событие в проекте с фиксированной датой. Вехи помогают
отслеживать прогресс по критическим точкам: релиз, запуск, сдача отчёта
заказчику.

### Создание вехи

1. Откройте проект → вкладка **Вехи**.
2. Нажмите **Создать веху**.
3. Укажите **Название** и **Дату**.
4. Привяжите задачи, которые должны быть завершены к этой дате.
5. Нажмите **Сохранить**.

### Отображение вех

- На канбан-доске вехи отображаются вертикальной линией с датой.
- На дашборде — в виджете **Ближайшие вехи**.
- В календаре — как отдельные события.

!!! warning "Просроченные вехи"
    Если дата вехи прошла, а задачи не закрыты, веха подсвечивается
    красным и попадает в отчёт **Проблемные проекты**.

## <a id="статусы-проектов">Статусы проектов</a>

| Статус | Описание |
| --- | --- |
| Активный | Проект в работе |
| На паузе | Работа приостановлена, задачи не двигаются |
| Завершён | Все задачи выполнены, проект закрыт |
| Архив | Проект доступен только для чтения |

## <a id="архив-и-восстановление">Архив и восстановление</a>

### Архивирование

Когда проект завершён, его можно архивировать:

1. Откройте **Настройки проекта**.
2. Нажмите **Архивировать**.
3. Подтвердите.

В архиве проект доступен только для чтения: задачи видны, но изменить
их нельзя.

### Восстановление

1. Откройте раздел **Проекты → Архив**.
2. Найдите проект.
3. Нажмите **Восстановить**.

Проект вернётся в статус **Активный**.

## <a id="настройки-проекта">Настройки проекта</a>

В разделе **Настройки проекта** доступны:

| Раздел | Что настраивается |
| --- | --- |
| Общие | Название, описание, сроки, тип |
| Участники | Роли и права |
| Доска | Колонки, WIP-лимиты, шаблоны |
| Уведомления | Кто и когда получает оповещения |
| Интеграции | Slack, email, webhooks |
| Опасная зона | Архивация, удаление проекта |

!!! warning "Удаление проекта"
    Удаление необратимо. Все задачи, комментарии и вложения исчезнут.
    Перед удалением рекомендуется архивировать проект.
