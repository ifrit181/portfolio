# Глоссарий

Термины и определения, используемые в документации TaskFlow.
Раздел помогает новым пользователям быстрее разобраться в системе,
а опытным — уточнить значение специфических понятий.

!!! note "Как пользоваться"
    Термины сгруппированы по категориям. Внутри каждой категории —
    алфавитный порядок. Если термин встречается в тексте документации
    впервые, на него ставится ссылка на эту страницу.

## <a id="продуктовые-термины">Продуктовые термины</a>

**TaskFlow**
: Система управления задачами и проектами. Позволяет планировать работу,
  распределять задачи, отслеживать прогресс и анализировать загрузку
  команды.

**Бэклог**
: Список всех задач проекта, ещё не распределённых по спринтам.
  Служит источником для планирования итераций.

**Дашборд**
: Главный экран пользователя. Содержит виджеты: задачи на сегодня,
  активность команды, график загрузки, ближайшие вехи.

**Организация**
: Верхний уровень в структуре TaskFlow. Включает всех пользователей,
  проекты и настройки. Соответствует компании или подразделению.

**Рабочее пространство**
: Синоним организации. Используется в API и настройках.

**Уведомление**
: Сообщение о событии в системе: новая задача, изменение статуса,
  комментарий с упоминанием. Отправляется по email, в интерфейсе
  или через push.

## <a id="работа-с-задачами">Работа с задачами</a>

**Задача**
: Базовая единица работы в TaskFlow. Из задач состоят проекты,
  спринты и чек-листы. У задачи есть название, описание, исполнитель,
  срок, приоритет и теги.

**Дочерняя задача**
: Задача, вложенная в другую задачу. Используется для декомпозиции
  крупной задачи на подзадачи с отдельными исполнителями.

**Канбан-доска**
: Представление задач в виде колонок по статусам. Карточки
  перетаскиваются между колонками, статус меняется автоматически.

**Карточка задачи**
: Компактное представление задачи на канбан-доске или в списке.
  Содержит название, исполнителя, приоритет и срок.

**Комментарий**
: Текстовое сообщение внутри задачи. Поддерживает упоминания через `@`,
  вложения и ссылки на другие задачи через `#`.

**Приоритет**
: Степень важности задачи. Значения: `Низкий`, `Средний`, `Высокий`,
  `Критический`.

**Связь между задачами**
: Отношение между двумя задачами: `Блокирует`, `Заблокирована`,
  `Дублирует`, `Связана с`.

**Тег**
: Метка для категоризации и фильтрации задач. У задачи может быть
  несколько тегов.

**Чек-лист**
: Список подшагов внутри задачи. Прогресс отображается на карточке
  в виде полосы: `3/5`.

## <a id="работа-с-проектами">Работа с проектами</a>

**Веха**
: Ключевое событие в проекте с фиксированной датой: релиз, запуск,
  сдача отчёта. Помогает отслеживать прогресс по критическим точкам.

**Диаграмма сгорания**
: График, показывающий, сколько работы осталось до конца спринта.
  Помогает понять, успевает ли команда закрыть задачи в срок.

**Проект**
: Контейнер для задач, объединённых общей целью. У проекта есть
  участники, сроки, статус и настройки.

**Спринт**
: Фиксированный промежуток времени (обычно 1–2 недели), в течение
  которого команда выполняет запланированный объём задач.

**Тип проекта**
: Способ организации работы: `Канбан` (непрерывный поток),
  `Scrum` (итерации), `Список` (без доски и спринтов).

**WIP-лимит**
: Ограничение на количество задач в колонке канбан-доски.
  Помогает не брать в работу больше, чем команда успевает делать.

## <a id="роли-и-права">Роли и права</a>

**Администратор**
: Роль с полным доступом к системе. Управляет пользователями,
  настройками, интеграциями и безопасностью.

**Владелец проекта**
: Роль с полным доступом к конкретному проекту. Может архивировать
  и удалять проект, назначать других участников.

**Менеджер**
: Роль с расширенными правами: управление проектами, спринтами,
  участниками, доступ к отчётам и массовым операциям.

**Наблюдатель**
: Роль только для чтения. Может просматривать задачи и проекты,
  но не может редактировать или комментировать.

**Сотрудник**
: Базовая роль. Может создавать и редактировать свои задачи,
  комментировать, просматривать проекты.

## <a id="статусы">Статусы</a>

### Статусы задач

| Статус | Что означает |
| --- | --- |
| Новая | Задача создана, не взята в работу |
| В работе | Исполнитель приступил |
| На проверке | Ожидает ревью |
| Готова | Проверена и завершена |
| Заблокирована | Есть препятствие |

### Статусы проектов

| Статус | Что означает |
| --- | --- |
| Активный | Проект в работе |
| На паузе | Работа приостановлена |
| Завершён | Все задачи выполнены, проект закрыт |
| Архив | Проект доступен только для чтения |

## <a id="отчёты-и-аналитика">Отчёты и аналитика</a>

**Дайджест**
: Регулярное письмо с обзором событий: задачи за неделю, ближайшие
  вехи, просроченные дедлайны. Отправляется по расписанию.

**Загрузка сотрудников**
: Отчёт, показывающий количество задач по каждому исполнителю
  и распределение по приоритетам. Помогает выявить перегрузку.

**Представление**
: Сохранённый набор фильтров для отчёта. Позволяет быстро открыть
  нужный срез данных без повторной настройки.

**Просроченная задача**
: Задача, у которой срок прошёл, но статус не `Готова`.

**Проблемная задача**
: Задача, которая долго не двигается: в статусе `В работе` более
  14 дней, в `На проверке` более 7 дней или без исполнителя более
  3 дней.

## <a id="технические-термины">Технические термины</a>

**API**
: Программный интерфейс для интеграции TaskFlow с внешними системами.
  Описан по стандарту OpenAPI, документация доступна в разделе
  [API](api/reference.md).

**Bearer-токен**
: Токен авторизации для API-запросов. Передаётся в заголовке
  `Authorization`. Создаётся в разделе **Профиль → API-токены**.

**Webhook**
: HTTP-уведомление, которое TaskFlow отправляет во внешнюю систему
  при наступлении события: создание задачи, изменение статуса,
  комментарий.

**SMTP**
: Протокол отправки email. Настраивается администратором
  в разделе **Настройки → SMTP** для рассылки уведомлений.

**2FA**
: Двухфакторная аутентификация. Дополнительный уровень защиты:
  кроме пароля требуется код из TOTP-приложения.

**CSV**
: Формат файла для массового импорта пользователей или экспорта
  задач.

**Роль**
: Набор прав пользователя в системе. Определяет, какие действия
  доступны: просмотр, редактирование, управление.
