# Настройки

Раздел **Администрирование** → **Настройки** доступен только
администраторам. Здесь настраиваются параметры системы, уведомления,
интеграции и безопасность.

## <a id="общие-настройки">Общие настройки</a>

| Параметр | Описание |
| --- | --- |
| Название системы | Отображается в заголовке, письмах, уведомлениях |
| Язык по умолчанию | Язык интерфейса для новых пользователей |
| Часовой пояс | Используется для сроков, отчётов, уведомлений |
| Формат даты | `ДД.ММ.ГГГГ`, `ММ/ДД/ГГГГ` или `ГГГГ-ММ-ДД` |
| Первый день недели | Понедельник или воскресенье |
| Логотип | Загружается в формате SVG или PNG, до 512×512 |

!!! note "Часовой пояс и отчёты"
    Все даты в отчётах хранятся в UTC, но отображаются в часовом поясе
    пользователя. Если сотрудник в другом регионе — он увидит своё время.

## <a id="уведомления">Уведомления</a>

### Типы уведомлений

| Событие | Email | В интерфейсе | Push |
| --- | --- | --- | --- |
| Новая задача | Опционально | Да | Да |
| Изменение статуса | Да | Да | Да |
| Напоминание о сроке | Да | Да | Да |
| Комментарий с упоминанием | Да | Да | Да |
| Еженедельный дайджест | Да | — | — |

Уведомления настраиваются на трёх уровнях:

1. **Системный** — что вообще возможно отправлять.
2. **Проектный** — что отправляется участникам конкретного проекта.
3. **Личный** — каждый пользователь может отключить часть уведомлений.

### Расписание дайджестов

Еженедельный дайджест отправляется по понедельникам в 9:00 по часовому
поясу пользователя. Можно изменить день и время в настройках.

## <a id="настройка-smtp">Настройка SMTP</a>

Для отправки email-уведомлений укажите параметры SMTP-сервера.

| Поле | Описание | Пример |
| --- | --- | --- |
| SMTP-хост | Адрес почтового сервера | `smtp.yandex.ru` |
| Порт | Порт подключения | `465` (SSL) или `587` (TLS) |
| Шифрование | SSL или TLS | `SSL` |
| Логин | Учётная запись отправителя | `noreply@company.com` |
| Пароль | Пароль или app-токен | `********` |
| Имя отправителя | Отображается в письмах | `TaskFlow` |

### Проверка настроек

После сохранения нажмите **Отправить тестовое письмо**. Укажите адрес —
система отправит письмо и покажет результат.

!!! warning "Пароли приложений"
    Для Gmail и Яндекс.Почты обычный пароль не подойдёт — нужен
    **пароль приложения**. Создайте его в настройках почтового аккаунта.

### Типовые ошибки SMTP

| Ошибка | Причина | Решение |
| --- | --- | --- |
| `Connection refused` | Неверный порт | Проверьте порт: 465 или 587 |
| `Authentication failed` | Неверный логин или пароль | Проверьте данные, используйте app-токен |
| `Certificate error` | Проблема с SSL-сертификатом | Включите TLS или обновите сертификаты |
| `Timeout` | Блокировка порта | Проверьте firewall и провайдера |

## <a id="интеграции">Интеграции</a>

### Slack

Подключение:

1. Откройте **Настройки → Интеграции → Slack**.
2. Нажмите **Подключить**.
3. Авторизуйтесь в Slack.
4. Выберите канал для уведомлений.
5. Настройте, какие события отправлять.

### Webhooks

Для интеграции с внешними системами настройте webhooks:

1. Нажмите **Добавить webhook**.
2. Укажите URL.
3. Выберите события: создание задачи, изменение статуса, комментарий.
4. Укажите секретный ключ для подписи.
5. Нажмите **Проверить** — система отправит тестовый запрос.

### API-токены

Для интеграций через REST API создайте токен:

1. Откройте **Настройки → Интеграции → API-токены**.
2. Нажмите **Создать токен**.
3. Укажите название и срок действия.
4. Выберите права (scope).
5. Скопируйте токен — он отобразится **один раз**.

!!! warning "Безопасность токенов"
    Не храните токены в открытом виде. Используйте переменные окружения
    или секреты в CI/CD. Отзывайте токены, которые больше не нужны.

## <a id="безопасность">Безопасность</a>

| Параметр | Описание |
| --- | --- |
| Минимальная длина пароля | По умолчанию 8 символов |
| Срок действия пароля | Через сколько дней требовать смену |
| Двухфакторная аутентификация | Обязательна / опциональна / отключена |
| Максимум попыток входа | После скольких неудач блокировать |
| Таймаут сессии | Через сколько минут неактивности выходить |
| IP-белый список | Ограничить доступ по IP |

### Двухфакторная аутентификация

Поддерживается через TOTP-приложения (Google Authenticator, Authy).

1. Откройте **Настройки → Безопасность**.
2. Включите **Требовать 2FA для администраторов**.
3. Пользователи при следующем входе настроят приложение.

## <a id="резервное-копирование">Резервное копирование</a>

### Автоматическое

1. Откройте **Настройки → Резервное копирование**.
2. Включите **Автоматическое резервное копирование**.
3. Укажите периодичность: ежедневно, еженедельно.
4. Укажите хранилище: локально, S3, Яндекс.Облако.
5. Укажите срок хранения: 7, 30, 90 дней.

### Ручное

Нажмите **Создать резервную копию** — система сохранит снимок базы
и вложений. Файл можно скачать.

!!! warning "Проверка восстановления"
    Раз в месяц проверяйте, что резервная копия восстанавливается.
    Непроверенная копия — это не копия.

## <a id="журналирование">Журналирование</a>

| Уровень | Что записывается |
| --- | --- |
| Error | Только ошибки |
| Warning | Ошибки и предупреждения |
| Info | Все значимые события (по умолчанию) |
| Debug | Подробная отладка (только для диагностики) |

Логи доступны в разделе **Администрирование → Журнал** и хранятся 30 дней.

## <a id="обслуживание">Обслуживание</a>

### Режим обслуживания

Включает заглушку для всех пользователей, кроме администраторов.
Используется при обновлении или миграции.

1. Откройте **Настройки → Обслуживание**.
2. Включите **Режим обслуживания**.
3. Укажите сообщение для пользователей.
4. Нажмите **Сохранить**.

### Очистка данных

Доступны операции:

- удаление корзины старше 30 дней;
- очистка старых логов;
- удаление неактивных пользователей;
- сброс кэша.

!!! warning "Перед очисткой"
    Убедитесь, что создана резервная копия. Откатить очистку нельзя.
