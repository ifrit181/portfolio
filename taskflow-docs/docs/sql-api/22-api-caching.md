## <a id="1-зачем-аналитику-кэширование">1. Зачем аналитику кэширование</a>

Кэш снижает нагрузку и latency, но добавляет сложность:
- устаревшие данные;
- непредсказуемое поведение.

Аналитик описывает, что можно кэшировать и на сколько.

---

## <a id="2-что-кэшируется">2. Что кэшируется</a>

| Тип данных | Кэшировать? |
|---|---|
| Справочники (страны, категории) | ✅ Долго |
| Каталог товаров | ✅ Средне |
| Данные пользователя | ⚠️ Осторожно |
| Заказы | ❌ Лучше не кэшировать |
| Курсы валют | ✅ Коротко |
| Результаты поиска | ✅ Коротко |

**Правило:** чем чаще меняются данные — тем короче TTL.

---

## <a id="3-http-кэш">3. HTTP-кэш</a>

Браузер и прокси кэшируют ответы по правилам сервера.

```
Клиент → [Кэш браузера] → [CDN] → [Nginx] → [App] → [БД]
```

---

## 4. Cache-Control

| Директива | Значение |
|---|---|
| `no-store` | Не кэшировать |
| `no-cache` | Кэшировать, но проверять каждый раз |
| `max-age=N` | Жить N секунд |
| `public` | Можно кэшировать везде |
| `private` | Только в браузере |
| `must-revalidate` | Проверять при истечении |

**Примеры:**

```http
Cache-Control: public, max-age=3600
Cache-Control: private, max-age=600
Cache-Control: no-store
```

## <a id="5-etag-и-условные-запросы">5. ETag и условные запросы</a>

### ETag

Сервер вычисляет хэш ресурса и передаёт в заголовке.

```http
GET /products/1

HTTP/1.1 200 OK
ETag: "v1-abc123"
Cache-Control: public, max-age=60
```

### If-None-Match

Клиент присылает ETag обратно:

```http
GET /products/1
If-None-Match: "v1-abc123"

HTTP/1.1 304 Not Modified
```

**Экономия:** не передаётся тело, только заголовки.

### Last-Modified + If-Modified-Since

Аналог по времени:

```http
Last-Modified: Wed, 14 Oct 2026 10:00:00 GMT

GET /products/1
If-Modified-Since: Wed, 14 Oct 2026 10:00:00 GMT
```

**Минус:** точность до секунды.

**Лучше:** ETag.

## <a id="6-кэш-на-стороне-клиента">6. Кэш на стороне клиента</a>

- Браузер (HTTP-кэш).
- SDK / клиентское приложение (in-memory).
- Service Worker (PWA).

**Что описывает аналитик:** TTL для клиентского кэша.

---

## <a id="7-кэш-на-стороне-сервера">7. Кэш на стороне сервера</a>

### Application cache

Кэш в памяти приложения (например, `caffeine` в Java).

**Что кэшируют:** справочники, дорогие вычисления.

### Distributed cache

Общий кэш между инстансами.

**Инструменты:** Redis, Memcached.

---

## 8. Redis

**Redis** — in-memory хранилище.

### <a id="типы-данных">Типы данных</a>

| Тип | Пример |
|---|---|
| String | `SET user:1:name "Иван"` |
| Hash | `HSET user:1 name "Иван" age 30` |
| List | `LPUSH queue "task1"` |
| Set | `SADD tags "sale"` |
| Sorted Set | `ZADD leaderboard 100 "user1"` |

### TTL

```redis
SET order:456:status "paid" EX 300
```

Через 300 секунд ключ удалится.

### <a id="паттерны">Паттерны</a>

- Cache-Aside: приложение само кладёт в кэш.
- Write-Through: запись идёт в кэш и БД.
- Write-Behind: сначала в кэш, потом асинхронно в БД.

### <a id="проблемы">Проблемы</a>

| Проблема | Что это |
|---|---|
| Cache stampede | Много клиентов одновременно запрашивают отсутствующий ключ |
| Cache penetration | Запросы к несуществующим ключам |
| Cache avalanche | Массовое истечение ключей |

**Решения:**
- mutex / singleflight;
- negative caching;
- jitter в TTL.

---

## <a id="9-инвалидация">9. Инвалидация</a>

**Самое сложное в кэше.**

| Стратегия | Когда |
|---|---|
| TTL | Просто, приемлемо |
| По событию | Точно, но сложно |
| Версионирование | Ключ меняется вместе с данными |
| Сброс по ключу | Точечно |

**Пример:** заказ изменился → удалить `order:456:*`.

---

## <a id="10-антипаттерны">10. Антипаттерны</a>

| Антипаттерн | Проблема |
|---|---|
| Кэшировать всё подряд | Устаревшие данные |
| Огромный TTL на изменяемых данных | Пользователь видит старое |
| Без инвалидации | Данные не обновляются |
| Кэш без метрик | Нет понимания hit rate |
| Кэшировать приватные данные в public | Утечка |

## <a id="11-практика">11. Практика</a>

### <a id="задача-1">Задача 1</a>
Опишите кэширование каталога товаров.

```http
GET /api/v1/products

HTTP/1.1 200 OK
Cache-Control: public, max-age=300, must-revalidate
ETag: "catalog-v42"
Vary: Accept-Language
```

**В ТЗ:** каталог кэшируется на 5 минут в браузере и CDN, инвалидация по событию `catalog.updated`.

### <a id="задача-2">Задача 2</a>
Опишите кэширование профиля пользователя.

```http
GET /api/v1/me

HTTP/1.1 200 OK
Cache-Control: private, no-store
```

**В ТЗ:** не кэшируется, потому что приватные данные.

### <a id="задача-3">Задача 3</a>
Опишите Redis-кэш для заказов.

```redis
SET order:456 EX 60
# при обновлении:
DEL order:456
```

**TTL:** 60 секунд, инвалидация по событию `order.updated`.

**Метрики:**
- hit rate > 90%;
- eviction rate < 5%;
- latency p95 < 5 ms.
