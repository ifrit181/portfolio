## <a id="3-логи">3. Логи</a>

### <a id="что-логировать">Что логировать</a>

- Входящие запросы (метод, путь, статус).
- Ошибки (код, сообщение, stack).
- Бизнес-события (`order.created`, `payment.failed`).
- Изменения данных (audit).

### <a id="формат">Формат</a>

**Структурированный JSON:**
```json
{
  "timestamp": "2026-10-14T10:30:00Z",
  "level": "INFO",
  "service": "orders",
  "trace_id": "abc123",
  "user_id": 123,
  "event": "order.created",
  "order_id": 456,
  "duration_ms": 45
}
```

### <a id="уровни">Уровни</a>

| Уровень | Когда |
|---|---|
| DEBUG | Разработка |
| INFO | Бизнес-события |
| WARN | Аномалии |
| ERROR | Ошибки |
| FATAL | Критично |

### <a id="что-не-логировать">Что НЕ логировать</a>

- Пароли.
- Токены.
- PII (полные номера карт, паспорта).
- Избыточные данные.

**В ТЗ:** список обязательных полей и запрещённых данных.

## <a id="4-метрики">4. Метрики</a>

### <a id="типы">Типы</a>

| Тип | Пример |
|---|---|
| Counter | Количество запросов |
| Gauge | Текущее значение |
| Histogram | Распределение (latency) |
| Summary | Квантили |

### <a id="что-измерять">Что измерять</a>

**RED:**
- **Rate** — запросов в секунду.
- **Errors** — доля ошибок.
- **Duration** — latency.

**USE (для ресурсов):**
- Utilization.
- Saturation.
- Errors.

### <a id="ключевые-метрики-api">Ключевые метрики API</a>

| Метрика | Формула |
|---|---|
| RPS | запросов / сек |
| Error rate | ошибок / всего |
| p50 / p95 / p99 latency | перцентили |
| Saturation | использование CPU / памяти |
| Throughput | обработано / сек |

### <a id="гистограммы">Гистограммы</a>

```
histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m]))
```

## <a id="5-трассировка">5. Трассировка</a>

**Distributed tracing** — путь запроса через микросервисы.

**Trace ID** — уникальный для всего запроса.
**Span** — часть работы (вызов сервиса, запрос в БД).

```
Trace abc123
├── Span: API Gateway (10ms)
├── Span: Orders Service (45ms)
│   ├── Span: DB query (5ms)
│   └── Span: Payment Service (30ms)
```

**Инструменты:** Jaeger, Zipkin, OpenTelemetry.

**В ТЗ:** требование передавать `X-Request-Id` между сервисами.

## 6. SLI, SLO, SLA

| Понятие | Значение |
|---|---|
| **SLI** | Индикатор (что измеряем) |
| **SLO** | Цель (какое значение хотим) |
| **SLA** | Обязательство перед клиентом |

**Пример:**
- SLI: p95 latency создания заказа.
- SLO: < 500 ms в 99% случаев за 30 дней.
- SLA: < 1000 ms, иначе компенсация.

### Error budget

Если SLO 99%, то 1% времени — бюджет на ошибки.
```
Месяц = 30 дней = 43200 минут
1% = 432 минуты недоступности
```

**В ТЗ:** указать SLO для каждой критичной операции.

## <a id="7-алерты">7. Алерты</a>

### <a id="по-чему-алертить">По чему алертить</a>

| Сигнал | Алерт |
|---|---|
| Error rate > 1% | Warning |
| Error rate > 5% | Critical |
| p95 latency > SLO | Warning |
| Сервис недоступен | Critical |
| Очередь растёт > N | Warning |
| DLQ не пуста | Warning |

### <a id="чего-избегать">Чего избегать</a>

- Алерт на каждый чих (alert fatigue).
- Алерт без действия.
- Алерт без контекста.

### <a id="что-должно-быть-в-алерте">Что должно быть в алерте</a>

- Что случилось.
- Где (сервис, endpoint).
- Когда началось.
- Ссылка на дашборд / логи.
- Что делать (runbook).

## <a id="10-практика">10. Практика</a>

### <a id="задача-1">Задача 1</a>
Опишите логирование создания заказа.

```json
{
  "timestamp": "2026-10-14T10:30:00Z",
  "level": "INFO",
  "service": "orders",
  "event": "order.created",
  "trace_id": "abc123",
  "user_id": 123,
  "order_id": 456,
  "external_id": "MAG-001",
  "total": 1990.00,
  "duration_ms": 45
}
```

**Запрещено:** токены, полные номера карт, пароли.

### <a id="задача-2">Задача 2</a>
Опишите метрики для API.

| Метрика | Тип | Описание |
|---|---|---|
| `http_requests_total` | Counter | Общее число запросов по кодам |
| `http_request_duration_seconds` | Histogram | Распределение latency |
| `http_requests_in_flight` | Gauge | Запросов в обработке |
| `orders_created_total` | Counter | Созданных заказов |
| `sync_errors_total` | Counter | Ошибок синхронизации |

### <a id="задача-3">Задача 3</a>
Опишите SLO.

| Операция | SLI | SLO |
|---|---|---|
| Создание заказа | p95 latency | < 500 ms |
| Список заказов | p95 latency | < 300 ms |
| API availability | success rate | ≥ 99.9% |
| Синхронизация с 1С | время | < 60 сек, 99% |

### <a id="задача-4">Задача 4</a>
Опишите алерты.

| Условие | Severity | Действие |
|---|---|---|
| error rate > 5% за 5 мин | Critical | PagerDuty |
| p95 > 1s за 10 мин | Warning | Slack |
| DLQ не пуста > 10 мин | Warning | Slack + email |
| sync errors > 100 за час | Warning | Slack |
