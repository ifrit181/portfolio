## 1. Что такое API

**API (Application Programming Interface)** — контракт, по которому одна система обращается к другой.

Примеры:
- Мобильное приложение → сервер.
- Интернет-магазин → платёжный шлюз.
- CRM → 1С.

**Аналитик проектирует** какие endpoint'ы нужны, какие поля передаются, что происходит при ошибках.

---

## 2. REST: принципы

**REST (Representational State Transfer)** — архитектурный стиль.

Ключевые принципы:
1. **Клиент-сервер** — разделение.
2. **Stateless** — каждый запрос независим, сервер не хранит состояние клиента.
3. **Кэшируемость** — ответы можно кэшировать.
4. **Единый интерфейс** — ресурсы, методы, коды.
5. **Слои** — клиент не знает, что за прокси/балансировщик.

---

## 3. Ресурсы и URL

**Ресурс** — сущность (пользователь, заказ, товар).

| Действие | URL | Метод |
|---|---|---|
| Список пользователей | `/users` | GET |
| Один пользователь | `/users/123` | GET |
| Создать пользователя | `/users` | POST |
| Обновить | `/users/123` | PUT/PATCH |
| Удалить | `/users/123` | DELETE |
| Заказы пользователя | `/users/123/orders` | GET |

**Правила:**
- существительные во множественном числе: `/users`, а не `/getUsers`;
- вложенность для связей: `/users/123/orders`;
- lowercase, дефисы: `/order-items`.

---

## 4. HTTP-методы

| Метод | Назначение | Идемпотентный | Безопасный |
|---|---|---|---|
| `GET` | Получить | ✅ | ✅ |
| `POST` | Создать | ❌ | ❌ |
| `PUT` | Полностью заменить | ✅ | ❌ |
| `PATCH` | Частично обновить | ❌* | ❌ |
| `DELETE` | Удалить | ✅ | ❌ |

*PATCH может быть идемпотентным, но не обязан.

**PUT vs PATCH:**
- PUT — заменяет объект целиком.
- PATCH — обновляет только переданные поля.

## 5. Статус-коды

### Успех (2xx)

| Код | Значение |
|---|---|
| `200 OK` | Успех |
| `201 Created` | Ресурс создан (POST) |
| `204 No Content` | Успех без тела (DELETE) |

### Ошибка клиента (4xx)

| Код | Значение |
|---|---|
| `400 Bad Request` | Невалидные данные |
| `401 Unauthorized` | Не аутентифицирован |
| `403 Forbidden` | Нет прав |
| `404 Not Found` | Не найдено |
| `409 Conflict` | Конфликт (например, дубль) |
| `422 Unprocessable Entity` | Валидация не пройдена |
| `429 Too Many Requests` | Превышен лимит |

### Ошибка сервера (5xx)

| Код | Значение |
|---|---|
| `500 Internal Server Error` | Ошибка сервера |
| `502 Bad Gateway` | Проблема с upstream |
| `503 Service Unavailable` | Сервис недоступен |
| `504 Gateway Timeout` | Таймаут |

## 6. Структура запроса

```
POST /api/v1/orders HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOi...
Accept: application/json

{
  "user_id": 123,
  "items": [
    { "product_id": 1, "quantity": 2 }
  ]
}
```

| Часть | Назначение |
|---|---|
| Метод + URL | Что делаем |
| `Host` | Куда |
| `Content-Type` | Формат тела запроса |
| `Authorization` | Аутентификация |
| `Accept` | Ожидаемый формат ответа |
| Body | Данные |

---

## 7. Структура ответа

**Успех:**
```json
{
  "id": 456,
  "user_id": 123,
  "status": "created",
  "total": 1990.00,
  "created_at": "2026-01-15T10:30:00Z"
}
```

**Ошибка:**
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "user_id is required",
    "details": [
      { "field": "user_id", "issue": "missing" }
    ]
  }
}
```

**Требования к описанию ошибок:**
- стабильный код ошибки;
- человекочитаемое сообщение;
- детали для отладки.

## 8. Пагинация, фильтрация, сортировка

### Пагинация

**Offset-based:**
```
GET /orders?page=2&limit=50
```
**Cursor-based (надёжнее):**
```
GET /orders?cursor=eyJpZCI6MTIzfQ&limit=50
```

### Фильтрация

```
GET /orders?status=paid&user_id=123&amount_gte=1000
```

### Сортировка

```
GET /orders?sort=-created_at,amount
```
`-` — убывание.

## 9. Версионирование

| Способ | Пример |
|---|---|
| В URL | `/api/v1/users` |
| В заголовке | `Accept: application/vnd.api.v1+json` |

На практике чаще всего — **в URL**.

## 10. Практика

### Задача 1
Опишите endpoint для получения списка заказов пользователя с фильтрами и пагинацией.

```http
GET /api/v1/users/123/orders?status=paid&page=1&limit=20&sort=-created_at
Authorization: Bearer <token>
```

**Ответ 200:**
```json
{
  "data": [
    { "id": 456, "amount": 1990, "status": "paid", "created_at": "2026-01-15T10:30:00Z" }
  ],
  "pagination": { "page": 1, "limit": 20, "total": 137 }
}
```

### Задача 2
Опишите сценарии ошибок для создания заказа.

| Код | Ситуация | Тело |
|---|---|---|
| 400 | Отсутствует `user_id` | `{"error": {"code": "VALIDATION_ERROR"}}` |
| 401 | Токен не передан | `{"error": {"code": "UNAUTHORIZED"}}` |
| 404 | `user_id` не найден | `{"error": {"code": "USER_NOT_FOUND"}}` |
| 409 | Дубль заказа | `{"error": {"code": "DUPLICATE_ORDER"}}` |
| 500 | Ошибка сервера | `{"error": {"code": "INTERNAL_ERROR"}}` |
