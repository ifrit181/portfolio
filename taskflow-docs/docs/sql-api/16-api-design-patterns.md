## <a id="1-зачем-аналитику-паттерны">1. Зачем аналитику паттерны</a>

Каждый API должен быть предсказуемым. Клиент, зная паттерны, не будет задавать лишних вопросов. Аналитик проектирует API так, чтобы разработчики разных команд делали его единообразно.

## <a id="2-именование-ресурсов">2. Именование ресурсов</a>

| Правило | ✅ Правильно | ❌ Неправильно |
|---|---|---|
| Существительные | `/users` | `/getUsers` |
| Множественное число | `/orders` | `/order` |
| Только lowercase | `/order-items` | `/OrderItems` |
| Вложенность для связей | `/users/123/orders` | `/getUserOrders?userId=123` |
| Без глаголов | `DELETE /orders/1` | `POST /deleteOrder/1` |
| Без расширений | `/products` | `/products.json` |

**Глубина вложенности** — не более 2 уровней. Дальше — отдельный ресурс.

```
✅ /users/123/orders
✅ /orders/456/items
❌ /users/123/orders/456/items/789
```

## <a id="3-пагинация">3. Пагинация</a>

### Offset-based

```http
GET /orders?page=1&limit=20
GET /orders?offset=40&limit=20
```

**Ответ:**
```json
{
  "data": [...],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 137,
    "total_pages": 7
  }
}
```

**Плюсы:** просто, можно прыгать по страницам.
**Минусы:** при вставке/удалении страницы «сдвигаются».

### Cursor-based

```http
GET /orders?cursor=eyJpZCI6MTIzfQ&limit=20
```

**Ответ:**
```json
{
  "data": [...],
  "next_cursor": "eyJpZCI6MTQzfQ"
}
```

**Плюсы:** стабильно при изменении данных.
**Минусы:** нельзя прыгнуть на страницу N.

### <a id="ключевая-пагинация">Ключевая пагинация</a>

```http
GET /orders?after_id=123&limit=20
```

### <a id="правила-для-тз">Правила для ТЗ</a>

- Максимальный `limit` (например, 100).
- Значение по умолчанию (например, 20).
- Что возвращать, если курсор невалиден (`400`).
- Всегда ли есть `total` (иногда дорого — лучше не возвращать).

## <a id="4-фильтрация-и-сортировка">4. Фильтрация и сортировка</a>

### <a id="простые-фильтры">Простые фильтры</a>

```http
GET /orders?status=paid&user_id=123
```

### <a id="операторы">Операторы</a>

| Синтаксис | Смысл |
|---|---|
| `?amount_gte=1000` | ≥ 1000 |
| `?amount_lte=5000` | ≤ 5000 |
| `?created_at_gte=2026-01-01` | С даты |
| `?status=paid,pending` | Один из |
| `?q=iphone` | Полнотекстовый поиск |

### <a id="сортировка">Сортировка</a>

```http
GET /orders?sort=-created_at,amount
```

`-` — убывание, `,` — несколько полей.

### <a id="что-описывать-в-тз">Что описывать в ТЗ</a>

- Какие поля можно фильтровать.
- Какие операторы поддерживаются.
- Какие поля доступны для сортировки.
- Поведение при неизвестном поле (`400` или игнор).

## <a id="5-формат-ответа">5. Формат ответа</a>

### <a id="один-ресурс">Один ресурс</a>

```json
{
  "id": 456,
  "user_id": 123,
  "status": "paid",
  "total": 1990.00,
  "created_at": "2026-10-14T10:30:00Z"
}
```

### <a id="коллекция">Коллекция</a>

```json
{
  "data": [
    { "id": 1, "name": "Товар A" },
    { "id": 2, "name": "Товар B" }
  ],
  "pagination": { "page": 1, "limit": 20, "total": 137 }
}
```

**Правило:** коллекция всегда обёрнута в объект с `data` — так проще добавлять метаданные.

### <a id="формат-полей">Формат полей</a>

| Поле | Формат |
|---|---|
| Дата/время | ISO 8601 (`2026-10-14T10:30:00Z`) |
| Деньги | Число + валюта отдельным полем |
| ID | Строка или число (в ТЗ явно) |
| Enum | Строки lowercase (`paid`, `pending`) |
| NULL | `null`, не отсутствие поля |

## <a id="6-формат-ошибок">6. Формат ошибок</a>

### <a id="единый-формат">Единый формат</a>

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Validation failed",
    "details": [
      { "field": "email", "issue": "invalid format" }
    ],
    "request_id": "8a7b3c1d-..."
  }
}
```

### <a id="что-важно">Что важно</a>

| Поле | Зачем |
|---|---|
| `code` | Стабильный код для программной обработки |
| `message` | Человекочитаемое сообщение |
| `details` | Список конкретных проблем |
| `request_id` | Для трассировки |

**В ТЗ:** перечислить все возможные `code` для каждого endpoint'а.

### <a id="примеры-кодов">Примеры кодов</a>

| Code | HTTP | Ситуация |
|---|---|---|
| `VALIDATION_ERROR` | 400 / 422 | Невалидные данные |
| `UNAUTHORIZED` | 401 | Нет токена |
| `TOKEN_EXPIRED` | 401 | Токен истёк |
| `FORBIDDEN` | 403 | Нет прав |
| `NOT_FOUND` | 404 | Ресурс не найден |
| `DUPLICATE` | 409 | Дубль |
| `RATE_LIMITED` | 429 | Лимит |
| `INTERNAL_ERROR` | 500 | Ошибка сервера |

## <a id="7-bulk-операции">7. Bulk-операции</a>

### Bulk create

```http
POST /api/v1/orders/bulk
{
  "items": [
    { "external_id": "A-1", "user_id": 1 },
    { "external_id": "A-2", "user_id": 2 }
  ]
}
```

**Ответ 207 Multi-Status:**
```json
{
  "results": [
    { "external_id": "A-1", "status": "created", "id": 101 },
    { "external_id": "A-2", "status": "error", "error": { "code": "DUPLICATE" } }
  ]
}
```

### <a id="правила-для-тз-2">Правила для ТЗ</a>

- Максимальный размер батча (например, 1000).
- Что происходит при частичной ошибке (атомарно или нет).
- Как сообщать об ошибках по каждой позиции.

## <a id="8-версионирование">8. Версионирование</a>

| Способ | Пример |
|---|---|
| В URL | `/api/v1/users` |
| В заголовке | `Accept: application/vnd.api.v1+json` |
| В query | `/users?version=1` |

**Практика:** версия в URL — самый простой и распространённый способ.

**Что описывать:**
- политика изменений (breaking / non-breaking);
- срок поддержки старых версий;
- как мигрировать клиентов.

### Breaking vs non-breaking

| Изменение | Breaking? |
|---|---|
| Добавить поле в ответ | ❌ |
| Добавить endpoint | ❌ |
| Убрать поле из ответа | ✅ |
| Переименовать поле | ✅ |
| Изменить тип поля | ✅ |
| Сделать необязательное поле обязательным | ✅ |
| Изменить формат ошибки | ✅ |

## <a id="9-hateoas-кратко">9. HATEOAS (кратко)</a>

Hypermedia As The Engine Of Application State — ответы содержат ссылки на связанные действия.

```json
{
  "id": 456,
  "status": "created",
  "_links": {
    "self":   { "href": "/api/v1/orders/456" },
    "cancel": { "href": "/api/v1/orders/456/cancel", "method": "POST" },
    "pay":    { "href": "/api/v1/orders/456/pay", "method": "POST" }
  }
}
```

**Редко используется** в реальных API, но встречается. Аналитик должен уметь это читать.
