# gost_pdf — генератор PDF по ГОСТ

Отдельный генератор PDF с оформлением по ГОСТ (ЕСПД/ГОСТ Р 7.0.97-2016) на основе
DOCX, который строит `avto_doc/generate_single.py`. Вывод — `site/assets/pdf-gost/`.
В `mkdocs.yml` хук **не подключён** (см. «Подключение как hook» ниже).

## Состав

| Файл | Назначение |
|---|---|
| `generate_pdf_gost.py` | CLI и mkdocs-hook: front matter → DOCX → ГОСТ-постобработка → 2-pass PDF |
| `gost_base.py` | программная база документа (стили, скелеты ЛИ/содержания) — **primer.docx не нужен** |
| `titlepage.py` | титульный лист по ГОСТ 19.104-78, п. 3.1–3.2 |
| `gost_styles.py` | структура документа (аннотация, содержание, ЛИ), поля/шрифты/колонтитулы, нумерация |
| `gost_check.py` | проверка каждого собранного PDF (титул, структура, разделы, колонтитулы, метаданные) и отчёт о расхождениях |
| `doc_types.py` | виды документов, обязательные разделы, обязательность информационной части |
| `gost/` | исходники стандартов (ГОСТ 19.x, 34.x, ГОСТ Р 7.0.97-2016 и др.) |
| `reference/matrix.md` | матрица требований стандартов и их реализация в генераторе |
| `reference/РЕКВИЗИТЫ.md` | front-matter ключи `gost_*` и их соответствие полям титула |
| `reference/front-matter.example.yaml` | полный пример front matter: все ключи и обязательные разделы (в комментариях) |

## Запуск

Все файлы (`docs/**/*.md`, кроме `snippets/`):

```bash
python -X utf8 gost_pdf/generate_pdf_gost.py
```

Фильтры:

```bash
python gost_pdf/generate_pdf_gost.py --only index.md,user-guide/tasks.md
python gost_pdf/generate_pdf_gost.py --doc-type rukovodstvo-polzovatelya
python gost_pdf/generate_pdf_gost.py --docs-dir docs --site-dir site
```

Отключение: переменная окружения `DOCX2PDF=off`.

После сборки для каждого PDF выполняются проверки (титульный лист, структура
и содержание, аннотация, обязательные разделы, колонтитулы, метаданные,
посторонний контент из шаблонов) — итоги пишутся в
`site/assets/pdf-gost/check-report.md` (сводная таблица, список расхождений,
полный список проверок по файлам). Свой путь отчёта: `--report <файл>`
или `--report off`.

## Тесты

```bash
python -m unittest discover -s taskflow-docs/gost_pdf/tests   # из корня репо
python -m unittest discover -s gost_pdf/tests                 # из taskflow-docs/
```

74 теста: юнит-тесты `gost_check.py` на синтетических PDF (без LibreOffice),
тесты разбора front matter/навигации/отчёта `generate_pdf_gost.py` и один
интеграционный тест полного цикла MD → DOCX → PDF → отчёт (требует `soffice`,
без него пропускается).

Зависимости: `python-docx`, `pyyaml`, `pypdf`, LibreOffice (`soffice` в PATH).
`avto_doc/primer.docx` не требуется — DOCX-база строится программно.

## Как это работает

1. Front matter отрезается во временный `.gost-tmp-*.md` рядом с исходным файлом
   (чтобы функции `generate_single.py`, читающие соседние файлы, работали как обычно).
2. `generate_single._prepare_docx()` строит DOCX; на время сборки у генератора
   подменён `_fresh_doc` → `gost_base.fresh_gost_doc()`: DOCX создаётся с нуля
   (стили, скелет листа регистрации изменений и поля содержания),
   титульный лист из `primer.docx` не используется.
3. `titlepage.apply()` заменяет блок титула на заполненный по реквизитам;
   `gost_styles.apply()` переносит/вставляет аннотацию, оформляет содержание,
   переименовывает «Изменения в документе» → «Лист регистрации изменений»,
   применяет поля/шрифты/абзацный отступ/колонтитулы/нумерацию.
4. Первый проход в PDF → извлечение фактических номеров страниц заголовков
   (LibreOffice не пересчитывает поле содержания) → второй проход с этими
   номерами и числом листов на титуле.
5. PDF очищается от инвертированных soft-mask (`_fix_soft_masks`) и кладётся в
   `site/assets/pdf-gost/<путь_исходника>.pdf`.
6. `gost_check.check_pdf()` проверяет готовый PDF (15–17 проверок на файл),
   `gost_check.build_report()` формирует `site/assets/pdf-gost/check-report.md`.

## Ограничения

- Оформление не изменяет `avto_doc/generate_single.py`: поддержка синтаксиса
  markdown (цитаты, ограждения кода, вложенные списки) остаётся такой, какая
  есть в этом генераторе.
- Первый H1 файла считается наименованием программы и в тексте не отображается
  (название попадает на титул).
- Лист утверждения не строится (ГОСТ 19.104-78, п. 2.1–2.5 — оформляется
  отдельным листом, в счёт листов не входит).

## Подключение как hook (опционально)

В `mkdocs.yml` (по желанию — в эту сборку не входит):

```yaml
hooks:
  - gost_pdf/generate_pdf_gost.py:on_post_build
```

Полная раскладка реквизитов и видов документов — в `reference/РЕКВИЗИТЫ.md`,
требования стандартов и приоритеты — в `reference/matrix.md`.
