# Как мы пишем и для кого

## Целевая аудитория

Мы пишем для разной аудитории, в связи с этим необходимо подбирать соответствующий стиль изложения и терминологию — жесткий технический текст для технического специалиста, и более простой и понятный для обычного пользователя.

Кто входит в нашу целевую аудиторию:

- инженеры внедрения,
- системные и бизнес-аналитики,
- диспетчера системы,
- сотрудники отделов маркетинга и продаж.

## Структура описаний форм, отчётов и справочников

Ниже описан рекомендуемый «скелет» статей про интерфейсные сущности. Он не является строгим шаблоном: если раздел не нужен — пропустите его, но порядок заголовков лучше сохранять.

### Общие правила для всех типов документов

- Один заголовок `H1` — это название формы/отчёта/справочника.
- Сразу после `H1` дайте краткое назначение: 1–3 предложения о том, что это и зачем нужно.
- Якоря для заголовков требуется добавлять только в описаниях форм, отчётов и справочников. Во вспомогательных/общих файлах, например `authorization.md`, `introduction.md`, `problems.md` и им подобных, заголовки можно оставлять без якорей.
- В описаниях форм, отчётов и справочников все заголовки оборачивайте в якорь:

  ```markdown
  ## <a id="как-открыть-форму">Как открыть форму</a>
  ```

- Если в документе больше трёх разделов, добавьте оглавление:

  ```markdown
  ## <a id="содержание">Содержание</a>

  - [Как открыть форму](#как-открыть-форму)
  - [Интерфейс формы](#интерфейс-формы)
  ```

- Для важных предупреждений используйте admonition:

  ```markdown
  !!! warning "Важно"

      Текст предупреждения.
  ```

- Примечания и другие сноски, которые не являются важными предупреждениями, оформляйте как admonition `note`:

  ```markdown
  !!! note "Примечание"

      Граничное значение в 300 сообщений задано в коде в виде константы и не доступно для изменения пользователями.
  ```

- Вложенные списки оформляйте с пустой строкой после родительского элемента и отступом 6 пробелов для дочерних элементов. После завершения блока вложенных элементов также добавьте пустую строку перед следующим элементом верхнего уровня:

  ```markdown
  - **Родительский элемент**:

        - **Дочерний элемент 1**: описание.
        - **Дочерний элемент 2**: описание.

  - **Следующий элемент**:
  ```

  Неправильно (элементы на той же строке или без пустой строки):

  ```markdown
  - **Родительский элемент**:    - **Дочерний элемент 1**: описание.
      - **Дочерний элемент 2**: описание.
  - **Следующий элемент**:
  ```

- В нумерованных списках с вложенными маркированными также добавляйте пустую строку после элемента верхнего уровня и используйте отступ 6 пробелов для дочерних элементов:

  ```markdown
  1. **Кнопки управления**:

        - **Скопировать** — копирует сменное задание из другой смены.
        - **По нормам** — задать планы через максимальную производительность или через планы карьера на смену по видам груза.
        - **Вручную** — установить план самостоятельно.
  ```

  Неправильно (без пустой строки или с неправильным отступом):

  ```markdown
  1. **Кнопки управления**:
     - **Скопировать** — копирует сменное задание из другой смены.
     - **По нормам** — задать планы.
  ```

- Изображения, примечания и прочее содержимое, относящееся к элементу вложенного списка, также оформляйте с отступом 6 пробелов:

  ```markdown
  1. Нажмите кнопку **Скопировать**.
  2. В открывшемся окне выберите дату и номер смены-источника.

        ![Диалог](assets/path/to/image.png){ .on-glb width="60%" }
        ///caption
        Окно копирования
        ///

        !!! note "Примечание"

            Текст примечания.


  3. Нажмите кнопку **Сохранить**.
  ```

- В таблицах разделительную строку между заголовком и телом оформляйте с пробелами по краям:

  ```markdown
  | Заголовок 1 | Заголовок 2 |
  | ----------- | ----------- |
  | Значение 1  | Значение 2  |
  ```

- Рисунки размещайте рядом с поясняющим текстом, используйте атрибуты `{ .on-glb width="" }` и подпись `///caption`. Для параметра `width` используйте правило:

  - **100%** — общие виды форм, справочников, отчётов, графиков и таблиц;
  - **60%** — отдельные окна, диалоги, панели, фильтры, подсказки и прочие элементы интерфейса;
  - **30px** — мелкие иконки, вставляемые внутрь строки.

  ```markdown
  ![Общий вид формы](assets/form_name/image_1.png "Общий вид формы"){ .on-glb width="100%" }
  ///caption
  Общий вид формы «Название»
  ///

  ![Окно фильтра](assets/form_name/image_2.png "Окно фильтра"){ .on-glb width="60%" }
  ///caption
  Окно фильтра
  ///

  Нажмите значок редактирования ![Значок](assets/form_name/edit_icon.png "Значок"){ width="30px" } в строке.
  ```

- В файле не должно быть двух пустых строк подряд.
- Файл всегда должен заканчиваться ровно одной пустой строкой: последний символ файла — `\n`, а перед ним находится непустая строка.
- Проверить можно командой:

  ```bash
  tail -c 1 file.md | od -An -tx1
  ```

  Корректный вывод: `0a`. Если вывод пустой или содержит несколько `0a` подряд, файл заканчивается не одной пустой строкой.

- Связанные документы перечисляйте в конце списком со ссылками.
- Не забудьте добавить новый файл в навигацию `data/mkdocs.yml`.

### Описание формы (оперативной формы)

Рекомендуемая структура:

1. **Назначение** — что позволяет делать форма.
2. **Как открыть форму** — пункт меню и техническое наименование.
3. **Подготовительные действия / Что нужно знать перед началом работы** — справочники, настройки и процедуры, которые должны быть заполнены или запущены.
4. **Интерфейс формы** — краткий обзор зон, кнопок, таблиц и шкал.
5. **Работа с данными** — пошаговые инструкции по основным операциям (создание, редактирование, удаление, копирование).
6. **Возможные проблемы и способы решения** — таблица «Проблема → Причина → Решение».
7. **Как данные формы используются в системе** — где ещё используются введённые здесь данные.
8. **Связанные формы и справочники** — ссылки на родственные документы.

Пример открытия формы:

```markdown
Чтобы открыть форму, воспользуйтесь одним из следующих способов:

- В строке меню выберите пункт **Качество → Оперативная форма качества складов**.
- Введите в строке поиска техническое наименование `unload_operative_view` и выберите форму в результатах поиска.
```

### Описание отчёта

Рекомендуемая структура:

1. **Назначение** — какие вопросы помогает решить отчёт.
2. **Как открыть отчёт** — пункт меню и техническое наименование.
3. **Как сформировать отчёт** — заполнение панели параметров.
4. **Описание полей результирующей таблицы** — список или таблица с расшифровкой колонок.
5. **Работа с результатами** — сортировка, фильтрация, настройка отображаемых столбцов, экспорт.
6. **Пример использования** — если отчёт сложный.

Для типовых операций с отчётами используйте сниппеты:

- [Сортировка, настройка столбцов и экспорт для обычных отчётов](./data/docs/general_snippets/reports/reports_snippets.md)
- [Сортировка, настройка столбцов и экспорт для форм нового фронта](./data/docs/general_snippets/reports/reports_snippets.md#сортировка-записей-в-отчете-для-форм-нового-фронта)
- [Варианты панели параметров](./data/docs/general_snippets/parameters_panel_snippets.md)

### Описание справочника

Рекомендуемая структура:

1. **Назначение** — какие объекты описывает справочник.
2. **Как открыть справочник** — пункт меню и техническое наименование.
3. **Подготовительные действия** — какие справочники и настройки должны быть заполнены заранее.
4. **Интерфейс справочника / Описание полей** — состав записи и назначение полей.
5. **Операции со справочником** — добавление, изменение, удаление, копирование, закрытие записей.
6. **Настройка отображения и фильтрация** — если есть нестандартные параметры.

Общий обзор функций справочника можно описывать стандартным текстовым фрагментом:

```markdown
Справочник содержит записи, которые представлены в форме списка. Каждая запись содержит набор полей с информацией об объекте. Вы можете [добавлять](#добавление), [изменять](#изменение) или [удалять](#удаление) записи справочника. Кроме того, доступна сортировка записей нажатием на заголовок поля. Повторное нажатие на заголовок поля меняет порядок сортировки.
```

Подробнее о стандартных фрагментах см. [шаблоны и стандартные текстовые фрагменты](./knowledge-base/templates-and-structures/text-samples.md).
